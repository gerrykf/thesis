# 文件上传成功但找不到的问题诊断

## 问题现象

- ✅ 后端返回成功：`{"success": true, "data": {"avatarUrl": "/uploads/avatars/13_xxx.png"}}`
- ❌ 文件在期望目录找不到：`/opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/`
- ❌ 访问URL返回404：`https://healthmanage.xin/uploads/avatars/13_xxx.png`

## 根本原因

**环境变量 `UPLOAD_PATH` 没有在1panel中生效**，导致：
1. 文件保存到了错误的位置（可能是相对路径解析的位置）
2. Nginx找不到文件（alias路径和实际文件位置不匹配）

---

## 立即诊断步骤

### 步骤1: 找到文件实际保存在哪里

在服务器上执行：

```bash
# 查找刚上传的文件
find /opt/1panel -name "13_1762018164368.png"

# 查找最近5分钟内创建的所有图片
find /opt/1panel -name "*.png" -mmin -5 -ls
```

**可能的位置**：
- `/opt/1panel/www/sites/healthbackend/index/server_upload/dist/uploads/avatars/` （编译后目录）
- `/opt/1panel/www/sites/healthbackend/index/server_upload/src/uploads/avatars/` （源码目录）
- `/opt/1panel/www/sites/healthbackend/index/uploads/avatars/` （项目根目录）

### 步骤2: 查看应用启动日志

在1panel管理面板查看应用日志，找到这几行：

```
[Upload] UPLOAD_PATH 环境变量: ???
[Upload] __dirname: ???
[Upload] 最终上传目录: ???
[Static] 静态文件目录: ???
```

**关键判断**：
- 如果 `UPLOAD_PATH 环境变量:` 后面是**空**或**undefined** → 环境变量没配置
- 如果 `最终上传目录` 不是 `/opt/.../uploads/avatars` → 路径配置错误

---

## 修复方案

### 方案1: 在1panel中配置环境变量（推荐）

#### 步骤1: 添加环境变量

在1panel管理面板：

1. 进入 **网站 -> healthbackend (Node.js项目) -> 环境变量**
2. 点击 **添加环境变量**
3. 添加：
   ```
   变量名: UPLOAD_PATH
   变量值: /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
   ```
4. 保存

#### 步骤2: 重启应用

在1panel管理面板点击 **重启** 按钮

#### 步骤3: 验证日志

查看应用启动日志，确认输出：

```
[Upload] UPLOAD_PATH 环境变量: /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
[Upload] __dirname: /opt/1panel/www/sites/healthbackend/index/server_upload/dist (或 src)
[Upload] 最终上传目录: /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars
[Static] 静态文件目录: /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

#### 步骤4: 移动已上传的文件（如果有）

如果之前已经上传了文件到错误位置，需要移动它们：

```bash
# 假设文件在 dist/uploads/avatars/
cd /opt/1panel/www/sites/healthbackend/index/server_upload

# 创建正确的目录
mkdir -p uploads/avatars

# 移动文件（根据实际位置调整）
mv dist/uploads/avatars/*.* uploads/avatars/ 2>/dev/null
# 或
mv src/uploads/avatars/*.* uploads/avatars/ 2>/dev/null

# 设置权限
chmod 755 uploads uploads/avatars
chmod 644 uploads/avatars/*
```

#### 步骤5: 测试上传

1. 上传新头像
2. 检查文件是否保存到正确位置：
   ```bash
   ls -lh /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/
   ```
3. 访问URL测试：
   ```bash
   curl -I https://healthmanage.xin/uploads/avatars/xxx.png
   ```

### 方案2: 使用 .env 文件（如果1panel不支持环境变量）

#### 步骤1: 确认1panel加载哪个 .env 文件

```bash
cd /opt/1panel/www/sites/healthbackend/index/server_upload

# 查看所有 .env 文件
ls -la .env*

# 查看1panel的启动配置
# （在1panel管理面板查看启动命令）
```

#### 步骤2: 修改正确的 .env 文件

假设1panel使用 `.env`：

```bash
# 备份原文件
cp .env .env.backup

# 编辑文件
nano .env

# 添加或修改
UPLOAD_PATH=/opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

保存后重启应用。

### 方案3: 创建软链接（临时方案）

如果文件保存在错误位置，又不想移动文件，可以创建软链接：

```bash
# 假设文件实际在 dist/uploads/avatars/
cd /opt/1panel/www/sites/healthbackend/index/server_upload

# 创建软链接
ln -s dist/uploads uploads

# 或者直接链接 avatars 目录
mkdir -p uploads
cd uploads
ln -s ../dist/uploads/avatars avatars
```

## 常见错误和解决方法

### 错误1: 环境变量配置后仍然无效

**原因**: 1panel可能没有重新加载环境变量

**解决**:
1. 完全停止应用
2. 等待5秒
3. 重新启动应用
4. 查看日志确认环境变量已加载

---

### 错误2: 文件保存成功但Nginx找不到

**原因**: Nginx alias 配置和实际文件位置不匹配

**检查**:
```bash
# 1. 确认文件位置
ls /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/

# 2. 确认Nginx配置
grep -A 5 "location /uploads/" /www/sites/frontend/vhost.conf

# 3. 确认alias路径正确
# 应该是: alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;
```

**修复Nginx配置**（如果路径不对）:
```nginx
location /uploads/ {
    alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;
    # 注意：末尾的 / 不能省略！
}
```

然后重载Nginx：
```bash
nginx -t && nginx -s reload
```

---

### 错误3: __dirname 指向了错误的目录

**原因**: TypeScript编译后，`__dirname` 指向 `dist/` 目录

**诊断**:
```
[Upload] __dirname: /opt/.../dist  ← 编译后的目录
```

**这是正常的**，代码使用相对路径 `../../uploads/avatars` 应该能正确解析到项目根目录。

但如果没有配置 `UPLOAD_PATH` 环境变量，则依赖相对路径，可能会出错。

**解决**: 务必配置 `UPLOAD_PATH` 环境变量（方案1）
