```

    ↓

文件路径: /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/13_xxx.png
```

## ✅ 配置清单

### 1. Nginx 配置（已完成 ✅）

**文件**: `h5-app.nginx` (第16-29行)

```nginx
location /uploads/ {
    alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;

    # 访问控制
    add_header Access-Control-Allow-Origin *;
    add_header Access-Control-Allow-Methods 'GET, OPTIONS';

    # 缓存策略
    expires 30d;
    add_header Cache-Control "public, immutable";

    # 安全设置
    autoindex off;
}
```

**状态**: ✅ **配置正确**

---

### 2. 后端环境变量配置

**文件**: `.env.development2`

```bash
# ✅ 正确配置（只到 uploads 目录，不包含 /avatars）
UPLOAD_PATH=/opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

**重要说明**:
- ⚠️ **不要**在末尾加 `/avatars`
- 代码会自动在此路径下创建 `avatars` 子目录

## 🔧 在1panel上的操作步骤

### 步骤1: SSH登录服务器

```bash
ssh root@your-server-ip
```

### 步骤2: 验证目录和文件

```bash
# 切换到项目目录
cd /opt/1panel/www/sites/healthbackend/index/server_upload

# 检查 uploads 目录是否存在
ls -la uploads/

# 检查 avatars 子目录
ls -la uploads/avatars/

# 如果目录不存在，创建它
mkdir -p uploads/avatars

# 设置权限（确保 Nginx 可以读取）
chmod -R 755 uploads
chown -R www-data:www-data uploads  # 或者 nginx:nginx，取决于系统
```

### 步骤3: 检查已上传的文件

```bash
# 查看所有头像文件
ls -lh uploads/avatars/

# 示例输出：
# -rw-r--r-- 1 www-data www-data 12K Jan 16 10:30 13_1762015881048.png
# -rw-r--r-- 1 www-data www-data 15K Jan 16 11:20 67_1762023456789.jpg
```

**检查要点**:
- 文件权限至少是 `644`（`-rw-r--r--`）
- Nginx 用户（通常是 `www-data` 或 `nginx`）能够读取

### 步骤4: 验证环境变量

```bash
# 查看 .env 文件中的 UPLOAD_PATH 配置
grep "UPLOAD_PATH" .env.development2

# 输出应该是：
# UPLOAD_PATH=/opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

**确认**:
- ✅ 路径以 `/uploads` 结尾
- ❌ **不应该**以 `/uploads/avatars` 结尾

### 步骤5: 重启服务

```bash
# 1. 测试 Nginx 配置
nginx -t

# 2. 如果配置正确，重载 Nginx
nginx -s reload

# 3. 在1panel管理面板重启 Node.js 应用
# （点击重启按钮）
```

### 步骤6: 测试访问

```bash
# 找一个已上传的文件
TEST_FILE=$(ls uploads/avatars/ | head -1)
echo "测试文件: $TEST_FILE"

# 测试 Nginx 静态文件服务
curl -I https://healthmanage.xin/uploads/avatars/$TEST_FILE

# 预期输出：
# HTTP/2 200
# content-type: image/png
# cache-control: public, immutable
# expires: ...
```

## 🐞 故障排查

### 问题1: 访问图片返回 404

#### 原因分析
1. 文件实际不存在
2. Nginx 配置未生效
3. 路径配置不一致

#### 解决步骤

```bash
# 1. 确认文件存在
ls -la /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/13_1762015881048.png

# 2. 如果文件存在但返回404，检查 Nginx 配置
nginx -t
nginx -s reload

# 3. 查看 Nginx 错误日志
tail -f /www/sites/frontend/log/error.log

# 4. 测试访问（添加详细输出）
curl -v https://healthmanage.xin/uploads/avatars/13_1762015881048.png
```

---

### 问题2: 上传成功但文件找不到

#### 原因
后端 `UPLOAD_PATH` 配置错误，文件上传到了错误的位置

#### 解决步骤

```bash
# 1. 查看 Node.js 应用日志（在1panel中）
# 找到这两行日志输出：
# [Upload] 最终上传目录: /opt/.../uploads/avatars
# [Static] 静态文件目录: /opt/.../uploads

# 2. 确认路径正确
# [Upload] 最终上传目录应该以 /avatars 结尾 ✅
# [Static] 静态文件目录应该以 /uploads 结尾 ✅

# 3. 如果路径不对，修改 .env.development2
nano .env.development2
# 修改为：
# UPLOAD_PATH=/opt/1panel/www/sites/healthbackend/index/server_upload/uploads

# 4. 在1panel中重启应用
```

---

### 问题3: 权限问题 (403 Forbidden)

#### 原因
Nginx 没有读取文件的权限

#### 解决步骤

```bash
# 1. 查看当前权限
ls -la /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/

# 2. 修改权限
chmod -R 755 /opt/1panel/www/sites/healthbackend/index/server_upload/uploads

# 3. 修改所有者为 Nginx 用户
# CentOS/RHEL
chown -R nginx:nginx /opt/1panel/www/sites/healthbackend/index/server_upload/uploads

# Ubuntu/Debian
chown -R www-data:www-data /opt/1panel/www/sites/healthbackend/index/server_upload/uploads

# 4. 重新测试
curl -I https://healthmanage.xin/uploads/avatars/13_1762015881048.png
```
