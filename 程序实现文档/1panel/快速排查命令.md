# 快速排查 404 问题

## 问题
访问 `https://healthmanage.xin/uploads/avatars/13_1762017388825.png` 返回 404

---

## 立即执行这些命令

### 1. 检查文件是否真的存在

```bash
# 查看 avatars 目录下所有文件
ls -lh /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/

# 查找这个具体文件
find /opt/1panel/www/sites/healthbackend -name "13_1762017388825.png"
```

**期望结果**：能看到文件 `13_1762017388825.png`

---

### 2. 检查文件权限

```bash
# 查看文件权限
ls -la /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/13_1762017388825.png
```

**期望结果**：
- 权限至少是 `644` (`-rw-r--r--`)
- 所有者应该是 `www-data` 或 `nginx`

**如果权限不对，执行**：
```bash
chmod 644 /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars/13_1762017388825.png
chmod 755 /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/avatars
chmod 755 /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

---

### 3. 检查 Nginx 配置

```bash
# 查看 Nginx 配置文件
cat /www/sites/frontend/vhost.conf | grep -A 10 "location /uploads/"
```

**期望结果**：
```nginx
location /uploads/ {
    alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;
    # ...
}
```

**关键点**：
- ✅ `alias` 后面的路径必须以 `/` 结尾
- ✅ 路径必须是：`/opt/1panel/www/sites/healthbackend/index/server_upload/uploads/`

---

### 4. 测试 Nginx 配置并重载

```bash
# 测试配置语法
nginx -t

# 如果测试通过，重载配置
nginx -s reload
```

---

### 5. 测试本地访问

```bash
# 测试本地访问（绕过域名和SSL）
curl -I http://localhost/uploads/avatars/13_1762017388825.png
```

**如果返回 200**：说明 Nginx 配置正确，可能是 SSL 或域名问题
**如果返回 404**：说明 Nginx 配置或文件路径有问题

---

### 6. 测试外部访问

```bash
# 测试完整URL
curl -I https://healthmanage.xin/uploads/avatars/13_1762017388825.png
```

---

### 7. 查看 Nginx 错误日志

```bash
# 查看最新的错误日志
tail -50 /www/sites/frontend/log/error.log
```

**常见错误**：
- `open() ... failed (2: No such file or directory)` - 文件不存在或路径错误
- `open() ... failed (13: Permission denied)` - 权限不足

## 最可能的原因

### 原因1: Nginx alias 配置问题

检查你的 Nginx 配置文件，确保：

```nginx
location /uploads/ {
    alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;
    # 注意：alias 后面的路径必须以 / 结尾！
}
```

**错误示例**（缺少末尾的 `/`）：
```nginx
alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads;  # ✗ 错误
```

**正确示例**：
```nginx
alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;  # ✓ 正确
```

---

### 原因2: 文件确实不存在

可能上传时保存到了错误的位置。

**检查方法**：
```bash
# 查找所有可能的位置
find /opt/1panel -name "13_1762017388825.png"

# 查看 Node.js 应用日志（在1panel管理面板）
# 找到上传时的日志，查看实际保存路径
```

---

### 原因3: 文件权限问题

**修复命令**：
```bash
chmod -R 755 /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
find /opt/1panel/www/sites/healthbackend/index/server_upload/uploads -type f -name "*.png" -exec chmod 644 {} \;
chown -R nginx:nginx /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
# 或者
chown -R www-data:www-data /opt/1panel/www/sites/healthbackend/index/server_upload/uploads
```

## 紧急修复（如果上面都不行）

如果以上都不行，尝试这个临时方案：

### 1. 让 Node.js 提供静态文件服务

修改 Nginx 配置，将 `/uploads/` 请求转发给 Node.js：

```nginx
# 注释掉或删除原来的 location /uploads/
# location /uploads/ {
#     alias /opt/1panel/www/sites/healthbackend/index/server_upload/uploads/;
#     ...
# }

# 添加新的配置，转发给 Node.js
location /uploads/ {
    proxy_pass http://127.0.0.1:3000;  # 你的 Node.js 端口
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

然后重载 Nginx：
```bash
nginx -s reload
```

这样就会由 Node.js 的 Express 静态服务提供文件。
