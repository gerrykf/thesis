# 头像上传功能修复总结

## 🐛 问题描述

用户在前端上传头像时遇到以下错误：

### H5端错误
```json
{
  "success": false,
  "message": "请上传头像文件"
}
```

### 管理后台端错误
```json
{
  "success": false,
  "message": "路径不存在: /uploads/avatars/17_1761580454997.png"
}
```

---

## 🔍 问题分析

### 问题1：静态文件路径错误
**文件**：`backend/src/app.ts`

**原因**：静态文件目录配置指向 `src/uploads`，但实际文件保存在项目根目录的 `uploads/`

**影响**：上传成功后无法访问图片，返回404错误

### 问题2：上传目录路径错误
**文件**：`backend/src/middleware/upload.ts`

**原因**：multer配置指向 `src/uploads/avatars`（相对路径计算错误），应该指向项目根目录的 `uploads/avatars`

**影响**：文件保存在错误的位置

### 问题3：FormData Content-Type被覆盖
**文件**：`frontend/h5-app/src/utils/request.ts`

**原因**：axios实例默认设置了 `Content-Type: application/json`，导致FormData的正确Content-Type（包含boundary）被覆盖

**影响**：后端multer无法解析FormData，`req.file` 为空

---

## ✅ 修复方案

### 修复1：修正后端静态文件路径

**文件**：`backend/src/app.ts:138-141`

```typescript
// 修复前
app.use('/uploads', express.static(path.join(__dirname, './uploads')));

// 修复后
app.use('/uploads', express.static(path.join(__dirname, '../uploads')));
console.log('[Static] 静态文件目录:', path.join(__dirname, '../uploads'));
```

**原理**：
- `__dirname` 指向编译后的 `dist/` 目录（或开发时的 `src/`）
- `../uploads` 正确指向项目根目录的 `uploads/`

### 修复2：修正multer上传目录

**文件**：`backend/src/middleware/upload.ts:5-9`

```typescript
// 修复前
const uploadDir = path.join(__dirname, '../uploads/avatars');

// 修复后
const uploadDir = path.join(__dirname, '../../uploads/avatars');
```

**路径解析**：
```
当前文件位置: src/middleware/upload.ts
__dirname:     src/middleware/
../../:        项目根目录
最终路径:      项目根目录/uploads/avatars
```

### 修复3：修正H5端请求Content-Type

**文件**：`frontend/h5-app/src/utils/request.ts:7-34`

```typescript
// 修复前
const request: AxiosInstance = axios.create({
  timeout: 15000,
  headers: {
    "Content-Type": "application/json", // ❌ 会覆盖FormData的Content-Type
  },
});

// 修复后
const request: AxiosInstance = axios.create({
  timeout: 15000,
});

request.interceptors.request.use((config) => {
  // ... token, locale 等配置

  // ✅ 如果是 FormData，让浏览器自动设置 Content-Type (包含 boundary)
  if (!(config.data instanceof FormData)) {
    config.headers["Content-Type"] = "application/json";
  }

  return config;
});
```

**原理**：
- FormData需要浏览器自动生成的 `multipart/form-data; boundary=----xxx` 格式
- 手动设置Content-Type会导致boundary丢失
- 只有非FormData请求才需要设置 `application/json`

## 📋 完整的上传流程

### 前端（H5端）

**文件**：`frontend/h5-app/src/views/my/index.vue:178-228`

```typescript
async function afterRead(file: UploaderFileListItem | UploaderFileListItem[]) {
  const fileItem = Array.isArray(file) ? file[0] : file;
  if (!fileItem?.file) return;

  isUploading.value = true;

  try {
    // ✅ 调用API（会自动创建FormData）
    const res = await postAuthAvatar({}, fileItem.file);

    const data = res as any;
    if (data.success && data.data?.avatarUrl) {
      // 更新store中的头像
      userStore.updateAvatar(data.data.avatarUrl);
      showToast('头像上传成功');

      setTimeout(() => {
        fileList.value = [];
        isUploading.value = false;
      }, 1000);
    }
  } catch (error: any) {
    showToast(error.message || '上传失败');
  }
}
```

### API层

**文件**：`frontend/h5-app/src/api/auth.ts:6-45`

```typescript
export async function postAuthAvatar(
  body: {},
  avatar?: File,
  options?: { [key: string]: any }
) {
  const formData = new FormData();

  // ✅ 添加avatar字段
  if (avatar) {
    formData.append("avatar", avatar);
  }

  // ✅ 发送请求（FormData会被正确处理）
  return request<{
    success?: boolean;
    message?: string;
    data?: { avatarUrl?: string };
  }>("/api/auth/avatar", {
    method: "POST",
    data: formData, // ✅ axios拦截器会检测到这是FormData
    ...(options || {}),
  });
}
```

### 后端（控制器）

**文件**：`backend/src/controllers/authController.ts:933-1002`

```typescript
export const uploadAvatar = async (req: AuthRequest, res: Response): Promise<void> => {
  try {
    // ✅ 检查文件是否存在
    if (!req.file) {
      res.status(400).json({
        success: false,
        message: "请上传头像文件",
      });
      return;
    }

    // ✅ 生成头像URL
    const avatarUrl = `/uploads/avatars/${req.file.filename}`;

    // ✅ 更新数据库
    await db.execute("UPDATE users SET avatar = ? WHERE id = ?", [
      avatarUrl,
      req.user?.userId,
    ]);

    // ✅ 删除旧头像文件
    if (oldAvatar && oldAvatar.startsWith("/uploads/avatars/")) {
      const oldAvatarPath = path.join(__dirname, "../../", oldAvatar);
      if (fs.existsSync(oldAvatarPath)) {
        fs.unlinkSync(oldAvatarPath);
      }
    }

    res.json({
      success: true,
      message: "头像上传成功",
      data: { avatarUrl },
    });
  } catch (error) {
    console.error("上传头像错误:", error);
    res.status(500).json({
      success: false,
      message: "服务器内部错误",
    });
  }
};
```

## 🎯 关键要点总结

### 1. FormData的正确处理
- ❌ 不要手动设置 `Content-Type`
- ✅ 让浏览器自动生成 `multipart/form-data; boundary=xxx`
- ✅ 在axios拦截器中判断 `config.data instanceof FormData`

### 2. 文件路径的正确配置
- ❌ 不要使用相对路径（如 `./uploads`）
- ✅ 使用 `path.join(__dirname, '../uploads')` 等明确的路径拼接
- ✅ 添加日志输出路径，方便调试

### 3. multer字段名匹配
- ✅ 前端FormData字段名必须是 `'avatar'`
- ✅ 后端multer配置必须是 `.single('avatar')`
- ❌ 字段名不匹配会导致 `req.file` 为空

### 4. 静态文件服务配置
- ✅ 静态目录必须与multer上传目录一致
- ✅ 访问URL路径：`/uploads/avatars/xxx.jpg`
- ✅ 物理存储路径：`项目根目录/uploads/avatars/xxx.jpg`
