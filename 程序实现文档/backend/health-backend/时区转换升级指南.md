# 时区转换功能升级指南

## 修改内容总结

### 1. 数据库修改 ✅
将 `record_date` 字段从 DATE 类型改为 DATETIME 类型

### 2. 后端验证规则修改 ✅
- `healthRoutes.ts`: 接受 ISO 8601 格式时间戳
- `dietRoutes.ts`: 接受 ISO 8601 格式时间戳

### 3. 前端提交逻辑修改 ✅
- `HealthForm.vue`: 发送带时区偏移的 ISO 8601 格式

## 升级步骤

### 步骤 1: 更新数据库字段类型

执行以下 SQL 命令：

```bash
mysql -u root -p000000 health_management
```

然后执行：

```sql
-- 修改健康记录表
ALTER TABLE health_records
MODIFY COLUMN record_date DATETIME NOT NULL COMMENT '记录日期时间';

-- 修改饮食记录表
ALTER TABLE diet_records
MODIFY COLUMN record_date DATETIME NOT NULL COMMENT '记录日期时间';

-- 验证修改
DESCRIBE health_records;
DESCRIBE diet_records;
```

### 步骤 2: 重启后端服务器

```bash
cd 程序实现文档/backend/health-backend
# 停止当前服务器 (Ctrl+C)
npm run dev
```

### 步骤 3: 刷新前端页面

重新加载浏览器页面即可。

## 功能说明

### 前端提交格式
用户在北京时间（UTC+8）12:43:26 提交打卡：
```json
{
  "record_date": "2025-12-27T12:43:26+08:00"
}
```

### 后端存储
转换为 UTC 时间存储：
```
2025-12-27 04:43:26 (UTC)
```

### 后端返回
返回 ISO 8601 格式：
```json
{
  "record_date": "2025-12-27T04:43:26.000Z"
}
```

### 前端显示
自动转换为用户本地时区：
- 北京用户看到：2025-12-27 12:43:26
- 柬埔寨用户看到：2025-12-27 11:43:26（UTC+7）

## 时区转换示例

### 场景：柬埔寨用户（UTC+7）在 23:00 提交

1. **前端发送**: `2025-12-27T23:00:00+07:00`
2. **后端存储**: `2025-12-27 16:00:00 (UTC)`
3. **后端返回**: `2025-12-27T16:00:00.000Z`
4. **柬埔寨用户显示**: 2025-12-27 23:00:00
5. **北京用户显示**: 2025-12-28 00:00:00

## 验证测试

1. 提交一条健康打卡记录
2. 检查控制台输出的 ISO 格式
3. 刷新页面查看日历是否正确显示
4. 检查数据库中存储的时间

## 注意事项

- ⚠️ 必须先执行 SQL 更新，否则后端会报错
- ⚠️ 旧数据的时间信息会丢失（只保留日期）
- ✅ 新提交的记录会保留完整的时间和时区信息
